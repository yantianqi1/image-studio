- image_job_items(status, priority desc, available_at, id)

调度逻辑：
1. Go worker claim ORDER BY priority DESC, available_at ASC, id ASC。
2. terminal failure 时：
   - item.status = failed
   - dead_letter_at = now()

3. retryable failure 时：
   - status queued
   - available_at = now + backoff
   - last_error_code/message 写入
4. 支持 exponential backoff：
   - base 5s
   - max 300s

- manual retry 清空 dead_letter_at，status 变 queued，available_at=now。
- manual_retry_count +1。
- 只能 admin 调用。

- priority 高的 item 先被 claim。
- retryable failure 使用 backoff。
- terminal failure 进入 dead letter。
- admin retry 能重新排队。
- dead-letter list 返回失败 item。

背景：

- job failed 后 release reservation。
- partial/retry 状态不提前处理 reservation。

   - apps/api/app/domains/billing/models.py
   - apps/api/app/domains/billing/service.py
   - image repository complete_job / mark_job_failed 相关逻辑
2. 在 Go runtime 增加 billing repository：
   - CommitReservation(ctx, tx, userID, reservationID)
   - ReleaseReservation(ctx, tx, userID, reservationID)
   - 幂等处理：已 committed/released 不重复扣款/释放。
3. 修改 parent aggregation：
   - aggregateParentJob 时，如果父 job 所有 items succeeded：
     a. job.status=succeeded
     b. commit reservation
   - 如果所有 items finished 且至少一个 terminal failed：
     a. job.status=failed
     b. release reservation
   - 如果仍有 queued/running/retry，不处理 reservation。

   - item completion/result insert/parent aggregation/reservation commit 必须在同一个 DB transaction 内。
   - 不要在 provider 调用期间持有 transaction。

   - 全部 item 成功后 reservation committed。
   - 任一最终失败且无 pending item 后 reservation released。
   - retry 中不处理 reservation。
   - 重复 aggregation 不重复扣款。
   - 匿名用户或 reservation_id null 时跳过 billing。
6. 文档：
   - docs/architecture/image-billing-flow.md
   - 说明 reservation 生命周期和 Go worker 责任。

限制：
- 不要改钱包表结构，除非确有必要。
- 不要改变价格计算逻辑。
- 不要在 Go worker 创建 reservation；创建仍由 API 负责。
- 不要破坏 Python admin 钱包页面。

- Go worker 完成父 job 时，钱包 reservation 状态正确。
