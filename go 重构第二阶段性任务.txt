目标：
加强 Go worker 在“文件写入”和“数据库写入”之间的一致性，避免出现：
- 文件已写入但 DB 事务失败造成孤儿文件
- DB 已写 asset 但文件缺失
- retry 时旧 result/asset 清理不完整
- 同一 item 重复完成导致重复 asset/result

请执行：
1. 审查当前 Go completion 流程
   - apps/worker-go/internal/jobs/render_store.go
   - apps/worker-go/internal/storage/*
   - image_job_results / assets 写入 SQL
   找出当前清理 old files、rollback、commit 的边界。

2. 引入 staged write 策略
   推荐流程：
   - 先把图片写到 staging path，例如 generated-assets/staging/{worker}/{uuid}.tmp
   - DB transaction 内创建 asset row 和 result row。
   - 根据 asset id 计算最终 storage_path。
   - commit 成功后 rename/move staging 到最终 path。
   - 如果 commit 失败，删除 staging。
   - 如果 rename 失败，标记 item 失败或进入 repair 状态，不能静默 succeeded。

   如果当前 storage 抽象不支持 rename，则增加接口：
   - WriteTemp(ctx, content, ext) TempObject
   - CommitTemp(ctx, temp, finalPath)
   - Delete(ctx, path)

3. 幂等处理
   - CompleteRenderedJob 必须锁定 image_job_items 当前 item。
   - 如果 item 已 succeeded，应不要重复写 result。
   - 对 image_job_results 增加唯一约束或在代码中保证：
     (job_id, result_index) 唯一。
   - 如果没有 DB 唯一约束，新增 Alembic migration。
   - retry 前清理同 result_index 的旧 result/asset。

4. 孤儿文件清理
   - 新增脚本或 Go 子命令：
     image-worker cleanup-orphan-assets
   - 扫描 local storage 中 asset-* 文件，对比 assets.storage_path。
   - dry-run 默认，只打印数量。
   - --execute 才删除。
   - 不要删除 uploads/ 和 comics/ 目录，除非明确属于 generated asset。

5. 测试
   - DB commit 失败时 temp 文件被删除。
   - storage final move 失败时 item 不应 succeeded。
   - 重复 CompleteRenderedJob 不产生重复 result。
   - retry 清理旧 result/asset。
   - cleanup dry-run 不删除文件。

限制：
- 不要破坏 Python storage 约定。
- 不要改变已有 storage_path 格式，除非有 migration。
- 不要默认执行删除操作。
- GCS 如果未支持，可以保持 unsupported，但接口要能扩展。

验收标准：
- 文件和 DB 状态更一致。
- orphan asset 有 dry-run 清理工具。
- result_index 不重复。
- go test ./... 通过。
- 最后总结一致性策略和失败处理。
