# 下一步并发重构方案：三路推进

当前适合从“两路并发”升级到 **三路并发**：

```txt id="z7v4c3"
Codex A：Go Core 写路径
目标：billing / quota / provider pricing 真正接入 Go Core API

Codex B：Go Runtime 控制面
目标：worker registry / dynamic config / drain / metrics / ops

Codex C：前端 + Admin + 灰度接入
目标：admin dashboard、nginx flag、文档、Python legacy shrink
```

这样可以比上一轮推进更快，同时避免大量冲突。当前仓库已有 `apps/worker-go`，Go module 使用 Go 1.23 和 `pgx/v5`。
Go worker 已经围绕 `image_job_items` 执行，并使用 `FOR UPDATE SKIP LOCKED` 领取任务。
`ImageJobItem` 模型也已经包含 queue pick、job result、running lease 相关索引。

# 第一批并发任务

## Codex A：Go Core 写路径

### 目标

把 Go Core API 从只读推进到核心写路径：

```txt id="a1-goal"
1. wallet reservation create / commit / release
2. quota check / consume / refund
3. pricing resolve
4. provider/model readonly cache
5. image create 前置商业校验 API
```

```text id="codex-a-next"

目标：
实现 Go Core API 的核心写路径，让后续 Go image API 创建任务时可以通过 Go Core 完成 billing、quota、pricing、provider 校验。

不要接管 public POST /api/public/image/jobs。
先实现内部 core API，供后续 image-api-go 调用。

请执行：

1. 确认或新增 apps/core-api-go

   如果不存在，新增：
   - cmd/core-api/main.go
   - internal/config

   阅读 Python 逻辑：

   - GetWallet

   - 使用 pgx transaction

   - apps/api/app/domains/public_quota/*

   - edit surcharge

   - POST /api/internal/core/billing/reservations
   - POST /api/internal/core/billing/reservations/{id}/commit
   - POST /api/internal/core/billing/reservations/{id}/release
   - POST /api/internal/core/quota/check
   - POST /api/internal/core/quota/consume
   - POST /api/internal/core/quota/refund

   /image/preflight 输入：
   - owner
   - model_code
   - mode
   - requested_count
   - reference_asset_count
   - has_client_provider_config
   - size
   - quality
   - request_ip

   输出：
   - provider_id
   - provider_model
   - resolved_price_cents
   - reservation_id 可选
   - quota_status
   - allowed true/false

7. Internal auth
   如果 runtime-go 已有 service auth，复用。
   如果没有，先实现简单 INTERNAL_SERVICE_TOKEN 校验。
   Header:
   - X-Internal-Service-Token

8. Audit
   对 reservation、quota consume、activation redeem 写 audit log。
   如果 audit_logs 表不存在，新增 migration。
   不记录 API key、Authorization、完整 prompt、base64 image。

9. 测试
   - billing reservation 幂等
   - quota consume/refund
   - pricing 与 Python 规则一致
   - preflight 成功

限制：
- 不要改 apps/worker-go 主循环。
- 不要改 apps/admin-web。
- 不要改 nginx。

验收标准：

- internal preflight 可供 Go image API 使用。
- billing/quota/pricing 单元测试通过。

- 最后总结新增接口、事务边界、测试结果。
```

## Codex B：Go Runtime 控制面

### 目标

把 Go worker 从“环境变量驱动”推进到“运行时可控”：

```txt id="b1-goal"
1. worker_nodes 注册
2. worker heartbeat
3. drain / resume
4. runtime config
5. metrics / readyz / pprof
6. queue ops 查询
```

### Codex B 提示词

```text id="codex-b-next"
你在 GitHub 仓库 yantianqi1/image-studio 中工作。请从仓库根目录开始。

分支建议：codex-b/runtime-control-plane

目标：
实现 Go Runtime 控制面，让 worker-go 支持注册、心跳、动态配置、drain/resume、metrics、readyz 和 queue ops。不要改 billing/quota/pricing 业务规则。

请执行：

1. 新增 migration
   创建表 worker_nodes：
   - id varchar(128) primary key
   - worker_name varchar(128) not null
   - hostname varchar(255)
   - version varchar(64)
   - status varchar(32) not null
   - mode varchar(32) not null
   - concurrency integer not null
   - started_at timestamp not null
   - last_heartbeat_at timestamp not null
   - metadata jsonb

   创建表 worker_runtime_config：
   - id bigserial primary key
   - config_key varchar(128) unique not null
   - config_value jsonb not null
   - updated_at timestamp not null

   创建表 runtime_ops_events：
   - id bigserial primary key
   - event_type varchar(64) not null
   - target_type varchar(64)
   - target_id varchar(128)
   - payload jsonb not null
   - created_at timestamp not null

2. apps/runtime-go/pkg/workercontrol
   实现：
   - RegisterWorker
   - HeartbeatWorker
   - MarkDraining
   - MarkStopped
   - LoadRuntimeConfig
   - UpdateRuntimeConfig
   - ListWorkers
   - GetWorker

   Worker 状态：
   - starting
   - running
   - draining
   - stopped
   - unhealthy

3. apps/worker-go 集成
   - 启动时注册 worker node。
   - 定期 heartbeat。
   - 收到 draining 状态后停止 claim 新任务。
   - running item 继续执行。
   - shutdown 时标记 stopped。
   - runtime config 可覆盖：
     concurrency
     poll interval
     provider concurrency default
     drain flag

4. Diagnostics HTTP
   如果尚未实现，新增：
   - GO_WORKER_HTTP_ADDR 默认 :7900
   - GET /healthz
   - GET /readyz
   - GET /metrics
   - /debug/pprof 仅 GO_ENABLE_PPROF=true 时启用

   readyz 检查：
   - DB ping
   - image_job_items 表存在
   - assets 表存在
   - storage 可写或可读

5. Metrics
   至少提供：
   - image_worker_claim_total
   - image_worker_claim_empty_total
   - image_worker_item_started_total
   - image_worker_item_succeeded_total
   - image_worker_item_failed_total
   - image_worker_item_retried_total
   - image_worker_running_items
   - image_worker_queue_wait_seconds
   - image_worker_render_duration_seconds
   - image_worker_heartbeat_failed_total

6. Ops query API
   如果 apps/core-api-go 已存在：
   - GET /api/admin/ops/workers
   - POST /api/admin/ops/workers/{id}/drain
   - POST /api/admin/ops/workers/{id}/resume
   - GET /api/admin/ops/image/queue-summary
   - GET /api/admin/ops/image/running-items

   如果 apps/core-api-go 不存在：
   - 只实现 runtime-go package 和 worker-go HTTP debug endpoints
   - 在文档写 TODO，避免阻塞

7. 文档
   新增：
   - docs/runbooks/worker-control-plane.md

   包含：
   - 如何 drain worker
   - 如何恢复 worker
   - 如何看 queue summary
   - 如何处理 stuck running item

8. 测试
   - register worker
   - heartbeat updates timestamp
   - drain stops new claim
   - running jobs continue
   - runtime config parses
   - healthz / readyz
   - metrics endpoint 包含指标名

限制：
- 不要改 billing/quota/pricing。
- 不要改 provider request payload。
- 不要改 public API。
- 不要默认开启 pprof。
- 不要让 drain 取消正在执行的 provider 请求。

验收标准：
- worker-go 可被注册和观察。
- worker 可 drain/resume。
- metrics/readyz 可用。
- go test ./... 通过。
- 最后总结 worker 状态机、API、配置和测试结果。
```
