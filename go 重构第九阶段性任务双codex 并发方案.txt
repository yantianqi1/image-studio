# 第 9 阶段：Go Image API 生产主路径确认

## 目标

把第八阶段从 blocked 推进到 complete。

## 前置条件

必须有 24h 生产或准生产 evidence：

```txt
create 5xx rate
render duration p95
queue wait p95
asset missing count
dead letter count
outbox pending age
worker heartbeat failed
provider failure rate
```

## 执行步骤

### 9.1 运行证据采集

在目标环境运行：

```bash
DATABASE_URL="$DATABASE_URL" \
RENDER_DURATION_P95_THRESHOLD_SECONDS=180 \
scripts/collect-go-image-api-cutover-evidence.sh
```

产出：

```txt
cutover evidence report
nginx log 统计
assetctl verify-assets 输出
DB queue / outbox / dead-letter 状态
worker metrics snapshot
```

### 9.2 checker 必须硬失败

你已经把文档改成“缺少真实生产证据时 checker 必须失败”，这个方向对。下一步要确认：

```txt
- 没有 synthetic success
- 没有 TODO pass
- 没有空报告 pass
- 没有缺 nginx log 仍 pass
- 没有 asset verify 缺失仍 pass
```

### 9.3 切流结论

根据 evidence 分三种：

| 结果         | 动作                                               |
| ---------- | ------------------------------------------------ |
| 全部 gate 通过 | 第八阶段标记 complete，Go image API create/read 进入默认主路径 |
| 小问题但可控     | Go read 默认，Go create 继续灰度                        |
| P0/P1 问题   | create 回滚到 FastAPI，Go worker 保持 image execution  |

## 验收标准

```txt
- 24h evidence 存档
- checker 通过
- runbook 更新
- rollback 仍可执行
- 第八阶段 goal complete
```

# 第 10 阶段：FastAPI Image Fallback 收缩

第九阶段通过后，才进入第十阶段。

## 目标

FastAPI 不再是 image 默认路径，只保留短期 fallback。

## 要做

### 10.1 Nginx 路由默认切 Go

生产推荐默认：

```env
GO_IMAGE_API_READS_ENABLED=true
GO_IMAGE_API_CREATE_ENABLED=true
GO_IMAGE_API_ASSETS_ENABLED=true
GO_IMAGE_API_SSE_ENABLED=true
```

保留：

```env
GO_IMAGE_API_FALLBACK_ENABLED=true
```

### 10.2 FastAPI image route 标记 fallback-only

文档和代码注释里明确：

```txt
FastAPI image routes:
- fallback only
- no new feature development
- no production execution logic
```

### 10.3 禁止 FastAPI image 新能力扩展

新增防回归测试或文档规则：

```txt
- 不允许 public create route 恢复 direct render
- 不允许 Python worker 默认消费 image_job_items
- 不允许新增 Python provider render 生产路径
- 不允许 README 推荐 Python image execution
```

### 10.4 设定 fallback 窗口

建议：

```txt
fallback 保留 1-2 个 release
或保留 7-14 天生产稳定期
```

通过后再删除或硬禁 FastAPI image write path。

## 验收标准

```txt
- Go image API 是默认 read/create 主路径
- FastAPI image 只作为 fallback
- Python image execution 不再是生产选项
- 文档、compose、nginx、tests 一致
```

# 第 11 阶段：Go Runtime 运营强化

这一阶段不是迁 FastAPI，而是补齐 Go 主路径长期运营能力。

## 11.1 Worker runtime config UI

你现在已经有 worker control plane 相关能力，但下一步要确认它能从后台操作：

```txt
- 查看 worker_nodes
- drain worker
- resume worker
- 修改 runtime config
- 查看 last heartbeat
- 查看 running item
```

Admin 页面需要能操作：

```txt
GO worker concurrency
provider concurrency
poll interval
drain mode
provider pause/resume
```

## 11.2 Provider runtime 管控

必须支持：

```txt
provider pause
provider resume
provider circuit open
provider circuit half-open
provider health check
provider failure rate
```

Worker claim 必须尊重 provider runtime state：

```txt
paused provider 不 claim
circuit_open provider 不 claim
degraded provider 降低并发
```

## 11.3 Dead Letter 运营闭环

Admin 必须能：

```txt
查看 dead letter item
查看 error_code / error_message
查看 attempt_count
manual retry
cancel
批量 retry
按 provider/model 筛选
```

## 11.4 Outbox 可靠性

补齐：

```txt
outbox pending oldest age
outbox retry attempts
outbox failed event
outbox replay
outbox cleanup
```

## 11.5 Asset 维护

补齐：

```txt
assetctl verify-assets
assetctl scan-orphans
assetctl rebuild-thumbnails
admin ops 入口
定期 runbook
```

## 验收标准

```txt
- 运营能在 admin 中看到和处理 Go runtime 问题
- provider 故障不会拖垮全局队列
- dead letter 不会静默堆积
- asset 缺失可以发现和修复
```

# 第 12 阶段：FastAPI 全局 Legacy 化评估

到这里再问：“是否彻底把 FastAPI 重构为 Go？”

不是现在立即做。第十二阶段先评估。

## 评估维度

### 1. FastAPI 剩余职责

列出 FastAPI 剩余模块：

```txt
auth
admin
settings
provider admin
comic
character library
uploads
gallery fallback
legacy image
public quota fallback
ops
```

逐项判断：

```txt
必须迁 Go
保留 Python
删除
fallback
```

### 2. API 流量占比

需要统计：

```txt
Go image API 流量占比
FastAPI public API 流量占比
FastAPI admin API 流量占比
FastAPI comic API 流量占比
FastAPI error rate
FastAPI p95 latency
```

### 3. 迁移收益

只有这些条件成立，才值得彻底 Go 化：

```txt
FastAPI 已无高频主链路
FastAPI 剩余功能少于 20%-30%
Go contract tests 已覆盖核心 payload
admin-web 已主要使用 Go ops
FastAPI 维护成本高于迁移成本
```

## 结论分支

| 评估结果                              | 动作                                 |
| --------------------------------- | ---------------------------------- |
| FastAPI 只剩 fallback/admin 低频      | 启动 FastAPI Sunset Plan             |
| FastAPI 仍承担 auth/admin/comic 大量功能 | 继续保留 FastAPI                       |
| FastAPI 和 Go 双写风险高                | 优先做 contract 和 route consolidation |
